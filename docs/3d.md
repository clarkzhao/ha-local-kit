# 3D 展示与 Blender

`frontend/demo/scene.json` 是全新虚构的两房布局，与原家庭户型无关。它保存可复现的几何、材质和实体绑定。Node 的 GLTFExporter 是快速构建 Adapter；Blender 是可编辑模型 Adapter，两者都生成 GLB + layout.json。

输入 `boxes` 使用米制 Blender 坐标 `[x,y,z]`，Z 向上；`size` 顺序相同。网页通过 GLTFLoader 接收 Y-up 模型，房间/标记二维坐标 `[x,y]` 映射为 Three.js `[x,height,-y]`。

每个可点设备在 GLB extras 中有 `entity_id`，对应 layout.models 中同名条目。`label` 用作标签；`screen_entity`、`curtain_entity`、`emissive_entity` 分别用于电视、窗帘和灯带状态。示例绑定仅为 `*.demo_*`，没有自动发现或写入真实实体注册表。

可选 Blender 构建：

```bash
blender -b --python scripts/build-blender-scene.py -- frontend/demo/scene.json .local/blender-demo
```

生成可编辑 `home.blend`、发布用 `home.glb` 以及 `layout.json`。将 GLB/layout 替换到前端输出目录，保留同一套卡片。发布 .blend 不是必须；公开时只分享虚构场景或确认允许分享的自有模型。

维护规则：

- 坐标原点、单位、轴向明确记录；缩放在导出前应用，GLB extras 保留稳定绑定。
- 材质使用 Principled BSDF；颜色从 sRGB 转 scene-linear，不用过度复杂着色网络。
- 模型几何表达设备位置；没有实时定位字段时，机器人保持配置的静态位置，不生成假轨迹。
- 先检查实体存在和状态可用性，动作由 HA 执行；演示 Adapter 只更新合成状态。
- 公开预览不包含真实住宅地图、门锁位置或设备标识。
- Node 演示构建和浏览器渲染已验证；可选 Blender 脚本单独列为可复现入口，未把未执行的 Blender 版本兼容性当作已经验证。

当前几何是轻量盒式模型，不是室内设计 CAD。可用 Blender 手工模型替换它，只要保持绑定契约和坐标约定。
